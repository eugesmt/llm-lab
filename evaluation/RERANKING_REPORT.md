# Отчёт: фильтрация, reranking и query rewrite

## 1. Цель эксперимента

Проверить, улучшает ли второй этап после FAISS качество найденного контекста:

```text
Обычный RAG:       вопрос → embedding → FAISS top-3 → LLM
Улучшенный RAG:    query rewrite → FAISS top-8 → фильтр → reranking → top-3 → LLM
```

Обычный и улучшенный режим передают модели одинаковое количество финальных
фрагментов — 3. Это позволяет сравнивать качество выбранных фрагментов, а не
просто количество контекста.

## 2. Настройки

| Параметр | Значение |
|---|---:|
| Embeddings | `qwen3-embedding:0.6b` |
| Размерность embedding | 1024 |
| Первичный поиск enhanced | top-8 |
| Порог similarity | 0.55 |
| Финальное количество chunks | top-3 |
| Reranking | heuristic |

Итоговый score для reranking:

```text
final_score = 0.75 × cosine_similarity + 0.25 × keyword_overlap
```

Отдельная модель reranker не использовалась.

## 3. Query rewrite

Для запроса на русском добавляются технические термины, которые встречаются в
английской документации.

Исходный вопрос:

```text
Как настроить входящий SIP-звонок?
```

Запрос для поиска:

```text
Как настроить входящий SIP-звонок?
inbound SIP trunk SIP dispatch rule CreateSIPTrunk CreateSIPDispatchRule
```

Финальный ответ модели по-прежнему строится на исходном вопросе пользователя.

## 4. Реальный результат retrieval

Вопрос:

```text
Как настроить входящий SIP-звонок?
```

FAISS нашёл 8 кандидатов. Все 8 прошли порог `similarity >= 0.55`:

| Место | Chunk | Similarity | Раздел |
|---:|---|---:|---|
| 1 | `structural_000486` | 0.9077 | Creating Bridge and Dispatch Rule |
| 2 | `structural_000487` | 0.8599 | Creating Bridge and Dispatch Rule |
| 3 | `structural_000480` | 0.7973 | Workflow |
| 4 | `structural_000485` | 0.7732 | Creating Bridge and Dispatch Rule |
| 5 | `structural_000479` | 0.6909 | Capabilities |
| 6 | `structural_000068` | 0.6858 | Features |
| 7 | `structural_000482` | 0.6683 | Config |
| 8 | `structural_000471` | 0.6618 | Adding an agent |

После reranking в LLM переданы:

| Место | Chunk | Similarity | Rerank score | Раздел |
|---:|---|---:|---:|---|
| 1 | `structural_000486` | 0.9077 | 0.8058 | Creating Bridge and Dispatch Rule |
| 2 | `structural_000480` | 0.7973 | 0.7730 | Workflow |
| 3 | `structural_000487` | 0.8599 | 0.7449 | Creating Bridge and Dispatch Rule |

Фактическая цепочка обработки:

```text
8 кандидатов → 8 прошли фильтр → 3 переданы LLM
```

## 5. Сравнение ответов в UI

### Обычный RAG

Выбранные источники:

```text
structural_000485
structural_000480
structural_000486
```

Ответ содержит подробности создания SIP Bridge, параметры входящих адресов,
аутентификации и затем создание SIP Dispatch Rule.

### Улучшенный RAG

Выбранные источники:

```text
structural_000486
structural_000480
structural_000487
```

Ответ содержит последовательность SIP Bridge → SIP Dispatch Rule, назначение
Dispatch Rule, поля `trunk_ids`, `hide_phone_number` и пример
`dispatchRuleDirect` с `roomName`.

## 6. Интерпретация

Оба режима нашли релевантную информацию. Улучшенный режим сфокусировался на
Dispatch Rule и примере направления звонка в комнату. Обычный режим сохранил
больше подробностей о начале настройки SIP Bridge.

Таким образом, reranking действительно меняет состав и порядок контекста, но
не гарантирует, что итоговый ответ всегда будет лучше. В данном примере:

- query rewrite улучшил совпадение с техническими терминами;
- FAISS расширил область поиска с 3 до 8 кандидатов;
- reranking выбрал 3 фрагмента из расширенного списка;
- фильтрация при пороге 0.55 ничего не удалила;
- улучшенный ответ стал более сфокусированным, но менее полным по настройке
  SIP Bridge.

## 7. Ограничения

Текущий эксперимент нельзя считать доказательством общего превосходства
улучшенного RAG, потому что:

1. проверка retrieval выполнена на отдельных вопросах;
2. для вопроса про SIP все 8 кандидатов прошли выбранный порог;
3. heuristic reranker использует простое совпадение терминов;
4. итоговое качество ответа требует ручной оценки полноты и точности;
5. соседние chunks одного раздела пока не объединяются автоматически.

## 8. Вывод

Улучшенный RAG реализован и работает по схеме:

```text
query rewrite → FAISS top-8 → similarity filter → heuristic reranking → top-3
```

На проверенном вопросе он изменил выбранные источники и порядок chunks. Для
следующего улучшения стоит добавить отображение промежуточной статистики в UI:

```text
FAISS: 8 → после фильтра: 8 → передано LLM: 3
```

и добавить в контрольный набор вопросы, на которых часть кандидатов имеет
низкую similarity и действительно удаляется фильтром.
